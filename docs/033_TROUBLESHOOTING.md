# Troubleshooting Guide

This guide provides solutions to common issues that may be encountered during the operation of WK Community OS.

---

### Issue 1: "Authorization Required" Error

*   **Symptom:** Users see a pop-up asking for authorization to run the script, or actions fail with an "Authorization Required" error in the logs.
*   **Cause:** The script is trying to perform an action (e.g., access Google Drive) that the user has not yet authorized. This often happens after new APIs or services are added.
*   **Solution:**
    1.  As an administrator, open the Apps Script editor.
    2.  Run any function manually (e.g., `runHealthChecks`).
    3.  A dialog box will appear asking for authorization. Click "Review permissions".
    4.  Choose your Google account, and on the "This app isn't verified" screen, click "Advanced", then "Go to [Project Name] (unsafe)".
    5.  Grant the requested permissions.
    6.  This process generally only needs to be done once by an admin after an update.

### Issue 2: Time-Based Triggers are Failing

*   **Symptom:** Notifications are not being sent, or analytics data is not updating. The "Executions" log shows failed runs for triggers.
*   **Cause:**
    *   **Quota Exceeded:** The script may have exceeded its daily runtime quota or other API quotas.
    *   **Code Error:** A recent code change may have introduced a bug that only manifests during trigger execution.
    *   **Permission Change:** The user who created the trigger may no longer have sufficient permissions.
*   **Solution:**
    1.  Check the error message in the "Executions" log for the specific reason.
    2.  If it's a quota issue, you may need to wait 24 hours or optimize the code to be more efficient.
    3.  If it's a code error, the development team needs to investigate and deploy a fix.
    4.  As a best practice, all triggers should be created by a dedicated service account or a long-term administrator account to avoid permission issues.

### Issue 3: Dashboards Show "Failed to load data"

*   **Symptom:** One or more widgets on a dashboard show an error message.
*   **Cause:** The `Analytics` package's aggregation process may have failed, or the data source for that specific widget is misconfigured.
*   **Solution:**
    1.  Manually run the daily analytics aggregation function (`runDailyAnalytics`). Check the logs for any errors during this process.
    2.  Verify that the `dataSource` property in the widget's definition (e.g., in `DashboardRTWidget.js`) correctly points to a valid method in the `Analytics` service or its providers.

### Issue 4: Generated PDF is Malformed or Empty

*   **Symptom:** The PDF document generated by the Letter Service is empty or does not have the data filled in correctly.
*   **Cause:**
    *   The Google Doc template has been modified, and a placeholder (e.g., `{{citizen.name}}`) was accidentally deleted or changed.
    *   The `LetterTemplateService` is not providing the correct data keys to match the placeholders in the template.
*   **Solution:**
    1.  Open the Google Doc template and compare its placeholders with the data keys being prepared in `LetterTemplateService.getTemplateData()`. Ensure they match exactly.
    2.  Check the version history of the Google Doc template to see if any unauthorized changes were made.
